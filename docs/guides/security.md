# Security and correctness invariants

> **When to read this:** Read before touching URL handling (`src/links.rs`, `src/images.rs`, `src/image_fetch.rs`, `src/read_url.rs`, `src/read_url_html.rs`, `src/read_url_sites.rs`), prompt assembly, tool registration or dispatch (`src/chat_client.rs`, `src/chat.rs`, `src/chat_style.rs`, `src/chat_tools.rs`, `src/tool_registry.rs`, `src/code_inspect.rs`), prompt/memory filtering (`src/memory.rs`), cookies (`src/cookies.rs`, `src/cookie_refresh.rs`, `tools/cookie_refresh_service.py`), or the self-improvement queue, auto-deploy, and sandbox (`src/improve_store.rs`, `src/improve_views.rs`, `src/improve_commands.rs`, `src/self_improve.rs`, `tools/self_improve_orchestrator.py`, `tools/auto_deploy.py`, `tools/omp_worker.py`).

## Read-only and forbidden paths

- `docs/communication-guide.md` is **read-only**. It is compiled into `maksut` via `include_str!("../docs/communication-guide.md")` in `src/chat_client.rs`. Never edit, reformat, or regenerate it; change bot behavior in code, `SYSTEM_PROMPT`, tool descriptions, `README.md`, or `docs/`.
- Self-improve forbidden paths (`docs/communication-guide.md`, `AGENTS.md`, `Dockerfile`, `compose.yaml`, `Cargo.lock`, `shell.nix`, `.github/`, `.env`, `.secrets/`, `cookie_refresh/`, `cookie-refresh/`, `packaging/`, `self-improve/`, `self_improve/`, `tools/self_improve_orchestrator.py`, `tools/self_improve_deploy.py`, `tools/auto_deploy.py`, `tools/pr_review.py`, `tools/omp_worker.py`, and `target/`) stay untouched by any automated worker tasks (policy for `tools/omp_worker.py` / future worker runs; live intake only creates GitHub issues via `tools/self_improve_orchestrator.py`).

## Untrusted URLs and SSRF gates

Every URL from a chat message, redirect header, metadata payload, or search result is untrusted.

- **Media URL allowlist (`src/links.rs`).** `allowed_url` accepts only `http`/`https` without credentials, explicit ports, or `%`-encoded path segments (which a server could decode into a redirect traversal), and matches exact host + post-path shapes for YouTube, Pinterest, X/Twitter, Instagram, and TikTok. `yt-dlp` runs with `--ies default,-generic` (`/etc/yt-dlp.conf`) so the generic extractor can never be reached via an embedded redirect.
- **Short-link resolution (`src/links.rs`).** `resolve_short_link` handles `pin.it`, `vm.tiktok.com`, and `vt.tiktok.com` manually (at most 5 redirects, `https` only, no credentials or port). Only `short_link_contact_allowed` hosts are dialed; regional Pinterest domains (`pinterest.<cc>`) are accepted in a `Location` header when `canonical_short_target` can extract the numeric `/pin/<id>/` directly without dialing them.
- **Photo CDN allowlist and DNS pinning (`src/images.rs`, `src/image_fetch.rs`).** `image_cdn_url` requires `https://` with no authority `@` or `:` (checked on the raw string before `Url::parse` normalizes `:443` away) and restricts hosts to `pinimg.com`, `cdninstagram.com`/`fbcdn.net`, `pbs.twimg.com/media/`, and signed `*.tiktokcdn*.com` (`x-signature` query required). `pinned_client` resolves the host on port 443, filters addresses through `permitted_ipv4`, disables proxies and redirects (`no_proxy()`, `redirect(Policy::none())`, `https_only(true)`), and pins the resolved socket addresses with `resolve_to_addrs`. Note that `permitted_ipv4` intentionally permits `198.18.0.0/15` because the host environment uses that range for transparent-proxy fake-IP routing; `read_url` below does **not** permit `198.18.0.0/15`.
- **TikTok cookies isolation (`src/images.rs`).** When fetching a TikTok photo post (`/@user/photo/<id>`), cookies from `COOKIES_FILE` are sent **only** to `https://www.tiktok.com` for the page HTML, never to CDN image hosts.
- **Public page reader (`src/read_url.rs`, `src/read_url_sites.rs`, [ADR 019](../adr/019-read-url.md)).** `read_url` is `ToolVisibility::All`, so for non-owners its target (after stripping any trailing `:1-120`, `:-80`, or `:raw` selector) must match an exact normalized URL from the current prompt, reply context, recent chat messages, or links returned by `web_search` / `research` / `read_url` in the current or recent turns of the same chat (`chat.discovered_url_ttl_secs` default 1800, `chat.discovered_urls_per_chat` default 32, checked via `allowed_target`); the owner may also open any valid public `http(s)` URL without query parameters. The model cannot invent a query-bearing URL to exfiltrate chat memory. Recognized public targets on `github.com`, `reddit.com`, `*.wikipedia.org`, `news.ycombinator.com`, `crates.io`, and `pypi.org` are rewritten to their fixed public raw/JSON API endpoints (`raw.githubusercontent.com`, `api.github.com`, `<lang>.wikipedia.org/api/rest_v1`, reddit `.json`, `hacker-news.firebaseio.com`, `crates.io/api`, `pypi.org/pypi`) before dialing. `read_url` rejects credentials, non-standard ports, IP literals, single-label hosts, `localhost`, `.local`/`.internal`/`.lan`/`.home.arpa`, IPv6-only hosts, and all non-public IPv4 (including `198.18.0.0/15`). Every hop is retried per `retry.read_url` (default 2 attempts, retrying transport errors and `408`/`429`/`500`/`502`/`503`/`504`), re-validated while the hop count stays within `read_url.max_redirects` (default 5, validation bounds the key to 1..=20), and dialed through a DNS-pinned client with no cookies, no proxy, a `read_url.max_bytes` body cap (default 2 MiB), a `read_url.total_timeout_secs` total deadline (default 20 s), and an HTML/XML complexity guard (`read_url.max_html_elements` default 20,000 elements, `read_url.max_html_depth` default 128); `:raw` slices return the cached unwrapped body text while `SYSTEM_PROMPT` and tool descriptions still mark all `read_url` output as untrusted data.

## Tool authorization and prompt boundaries

- **Single authorization point (`src/tool_registry.rs`, [ADR 015](../adr/015-tool-registry.md)).** `ToolRegistry::find(name, owner)` is the only gate between a model tool call and execution. Never check tool names against a separate string list. Adding a `ToolVisibility::All` tool exposes it to every user in every enabled group (`web_search`, `research`, `read_url`, `propose_feature`, `feature_status`, `inspect_code`, `find_stickers`, `send_sticker`); tools that mutate global self-memory or inspect the owner's approval queue (`feature_confirmation`, `remember_self`) must stay `ToolVisibility::Owner`.
- **Owner-only prompt isolation (`src/chat.rs`, `src/chat_client.rs`).** Instructions for `Owner` tools (`OWNER_CODE_PROMPT` for `remember_self`, `OWNER_FEATURE_PROMPT` for `feature_confirmation`) are appended only when `owner == true` (and when the queue context is present). Never mention owner-only tools in `SYSTEM_PROMPT`.
- **Post-research privilege reduction (`src/tool_registry.rs`, `src/chat_tools.rs`, [ADR 016](../adr/016-research.md)).** Search results and `read_url` pages are untrusted data. After a successful `research` pass, both `payload_for_mode` and the tool dispatcher restrict available tools to read-only tools (`web_search`, `research`, `read_url`, `inspect_code`) unless the user's own prompt explicitly asked for a sticker or a feature.
- **Snapshot confinement and self-memory (`src/code_inspect.rs`, [ADR 018](../adr/018-owner-code-inspection.md)).** `inspect_code` (`ToolVisibility::All`) canonicalizes `base` (`/var/lib/maksut/code`), canonicalizes any requested relative path, verifies `candidate.starts_with(&base)`, rejects a directly requested file whose path below `base` contains a hidden or skipped component, skips symlinks during directory traversal, skips `.git`, `target`, `self-improve`, `self_improve`, `cookies`, `.secrets`, and `node_modules`, and allows only `rs`, `toml`, `md`, `py`, `yaml`, `yml`, `json`, and `sh` files up to 256 KiB. `remember_self` (`ToolVisibility::Owner`) has two modes: when `source_url` is provided, it requires `inspect_code` in the same turn, validates `source_url` against `https://github.com/labi-le/maxwell/blob/main/<path>[#L<n>]` and `safe_path`, and runs both `topic` and `fact` through `detect_flags` and `validate_summary`; when `source_url` is empty, it stores an owner conversational directive/note (`- [owner] <topic>: <fact>`, rejecting secrets and URLs, or deleting the topic when `fact` is empty), and caps `bot_self_memory` at 50 rows / 1200 prompt chars. Both `format_line_with_owner` (`src/memory.rs`) and `record_self_fact` / `load_self_memory` (`src/code_inspect.rs`) neutralize literal `[owner]` substrings inside user-controlled `author_name`, `text`, `topic`, and `fact` fields (`[ owner ]`) so non-owners cannot forge the `[owner]` header tag.

## Prompt injection and chat memory hygiene

- **Two-tier lexical detection (`src/memory.rs`, [ADR 014](../adr/014-injection-ignore.md)).**
  - `detect_flags` marks messages with `FLAG_INJECTION` (1), `FLAG_SECRET` (2), or `FLAG_JUNK` (4). Flagged rows remain in `chat_messages` for audit but are excluded from `load_memory` and `compact_chat` (`WHERE flags = 0`). Its `FLAG_SECRET` rule is intentionally coarse — 40+ ASCII alphanumerics in the text with at least one digit — because it guards memory hygiene, not egress; text about to be published to `telegra.ph` is checked by `credential_like` (unconditional markers, an `api_key`/`api key` name followed by `=` or `:`, or one contiguous `[A-Za-z0-9_-]` run of 32+ characters with a digit), which avoids the whole-text false positive but still withholds articles containing key-shaped runs such as hex digests, UUIDs, or long digit-bearing identifiers.
  - `injection_attempt` checks a narrower list of high-confidence override markers (`INJECTION_MARKERS`). When a non-owner triggers `injection_attempt` in an enabled group, the bot records `user_id` in `ignored_users` for `memory.ignore_secs` (default 86_400, 24 hours, non-extending while active) and marks their messages with `FLAG_IGNORED` (8). Ignored users receive no replies and no `answerCallbackQuery`. `OWNER_ID` is never ignored.

## Secrets, diagnostics, and sandbox isolation

- **No raw stderr or secret echoes ([ADR 006](../adr/006-albums-errors-cache.md), [ADR 008](../adr/008-docker-cookie-refresh-service.md)).** Never send raw `yt-dlp` / `ffmpeg` stderr, API response bodies, diagnostic URLs with query parameters, `.env`, or `cookies.txt` to Telegram or SQLite. `download_failures` stores only `url_host`, `url_path` (without query), static `stage`, static `detail`, and `exit_code`.
- **Cookie refresh privilege separation.** The `maksut` container mounts `/run/secrets/maksut` read-only and has no SSH client or key. Only the `cookie-refresh` sidecar mounts `.secrets/cookie-refresh` (`ro`) and `/run/secrets/maksut` (`rw`).
- **Self-improve approval isolation.**
  - Neither `feature_status` nor `feature_confirmation` can approve, reject, or mutate queue state. Only an owner inline-button callback (`handle_callback`) or an explicit owner command in a private chat (never forwarded, never in a group) writes to `approvals/` or `rejections/`.
  - When approved, `tools/self_improve_orchestrator.py` opens a GitHub issue via `gh issue create` using a temp body file (`--body-file`), never passing user text through a shell.
