## Activation and addressing (`src/chat.rs`, `src/chat_client.rs`, `src/handler.rs`, [ADR 012](../adr/012-free-chat.md))

- Free chat is enabled when `LLM_API_KEY` is non-empty (`LLM_BASE_URL` defaults to `https://llm.labile.cc/v1`, `LLM_MODEL` to `deepseek-v4.1-flash`). Without `LLM_API_KEY`, the bot operates as a link downloader and classic sticker responder only.
- **Reasoning:** `ChatConfig::complete` asks for deliberation on the first attempt (`llm.reasoning_effort`, overridden by `LLM_REASONING_EFFORT`, default `low`; `none` or an empty value omits the field). A reply with no content and no tool call is retried once without deliberation (`reply_is_empty` in `src/chat_style.rs`), and vision turns always start without it.
- **Private chat:** responds to `OWNER_ID` on any non-command message that has no supported media link and did not fire a standalone sticker trigger.
- **Enabled group (`/maksut on`):** responds when addressed via `@<bot_username>`, a reply to the bot's message, or common inflected forms of `максут` / `максутка` / `maksut` (`BOT_NAME_FORMS` in `src/chat_style.rs`, stripped at the start/end of the prompt while preserved mid-sentence so third-person questions keep their subject; `максвелл` is not a chat trigger). Repetitive copy-paste spam from a non-owner (3+ consecutive messages from that user with the same normalized text in recent history, checked via `is_repeated_user_spam`) is suppressed without calling the model. Turns within the same chat hold a shared `read()` guard on `Settings::chat_lock(chat_id)` (so `memory_compactor`'s exclusive `write()` guard cannot compact a chat mid-turn) and an exclusive `write()` guard on `Settings::user_turn_lock(chat_id, sender.id)` (`src/chat.rs`) so burst messages from the same participant see the bot's immediately preceding reply in order while different participants in the same group run concurrently under `chat.concurrency` (default 4). After the bot replies in a group, it keeps a 3-minute active-conversation window (`chat.followup_window_secs` default 180, capped at `chat.max_active_chats` default 1024) for that chat so any participant in the ongoing thread can continue the exchange without repeating `максут` or replying to the bot's message (including replies to other thread messages, with the replied-to snippet passed via `reply_context`, text replies to messages carrying a photo/image-document with the replied-to image downloaded for vision, and new photo/image-document messages carrying a non-empty caption in the active thread; bare uncaptioned photos without a bot mention or reply to the bot are ignored during followup); explicit shut-up phrases (`is_stop_followup`) from any participant clear the followup window (and never refresh `note_reply`), and `FOLLOWUP_PROMPT` instructs the model to reply with `PASS` (checked via `is_pass_reply`) when the message is repetitive spam, a closed remark, a bare reaction sticker, another participant's unaddressed screenshot, third-person chatter between other participants, or off-topic.
- **Delivery:** both private and group replies (first text chunk, button prompt, and stickers) attach `reply_parameters` (`ReplyParameters::new(message.id)`) with `disable_notification = true` and split at `chat.reply_max_chars` (default 3900).
- **Lookup ack:** every `web_search`, `research`, `read_url`, and `inspect_code` pass fires a non-blocking `tokio::spawn` to set the `👀` reaction on the triggering message (`mark_lookup` in `src/reaction.rs`) without awaiting Telegram before starting the lookup; repeating the same reaction is a Telegram no-op, so passes carry no state about it. The reaction is best effort: disabled group reactions, a deleted message, or a Telegram error never delay or fail the answer.
- **Rate limits and budgets:** per-user cooldown `chat.cooldown_ms` (default 3000), group followup window `chat.followup_window_secs` (default 180, cleared immediately on any `is_stop_followup` phrase), `chat.concurrency` (default 4), `llm.request_timeout_secs` (default 40) with retries from `retry.llm` (default 2 attempts, retrying transport errors and `408`/`500`/`502`/`503`/`504` in `ChatConfig::complete_with`), `chat.max_tokens` (default 900, `chat.status_max_tokens` default 1200, `chat.research_max_tokens` default 1500), up to `chat.tool_rounds` (default 8) tool iterations per reply, with `chat.typing_keepalive_secs` (default 4). Each turn also injects the current Moscow timestamp (`format_moscow_time`, `UTC+3`) and up to `chat.discovered_urls_per_chat` (default 32) recently discovered URLs in that chat (`chat.discovered_url_ttl_secs` default 1800).

## Voice and styling (`src/chat_style.rs`, `src/chat_client.rs`)

- `docs/communication-guide.md` is compiled into the binary (`COMMUNICATION_GUIDE = include_str!("../docs/communication-guide.md")`) and prepended to every chat's system prompt, followed by `GUIDE_PREFIX` and `SYSTEM_PROMPT`, which take precedence. Never edit `docs/communication-guide.md`.
- Normal replies pass through `style_reply`: casing is left exactly as the model wrote it (the prompt asks for mostly lowercase, so capital letters are the model's choice, not the delivery path's), prose lines joined into one while fenced code blocks (three- or four-backtick fences) keep their own line breaks, indentation and backticks verbatim, em/en dashes (`—`, `–`) replaced with `-` and bare repository file paths (`src/...`, `docs/...`, `tools/...`, `Cargo.toml`) expanded into full `https://github.com/labi-le/maxwell/blob/main/...` links via `expand_repo_blob_links` in prose only, a safety cap of `chat.reply_max_chars` (default 3900) applied afterward by `shorten` (which cuts at the last whitespace before `max_chars` so a reply never ends mid-word), and trailing `.`/`…` stripped unless the reply ends inside an unterminated code fence. It leaves `@username` mentions intact; only research sources pass through `sanitize_research_text`, which renders `@` as a space.
- Research replies pass through `style_research_reply`: casing and paragraphs preserved, body capped at `chat.research_body_chars` (default 4800), total with the bot-appended `источники:` block capped at `chat.research_max_chars` (default 6000). In live chat (`SYSTEM_PROMPT` and the research mode prompt in `src/chat.rs`), research answers default to 1-2 dense paragraphs with the direct conclusion, key figures, and `[n]` citations (no boilerplate headings such as `короткий вывод:` / `цены:` / `итог:`), expanding to 3-4 paragraphs only when the user explicitly asks for a detailed report.

## Vision attachments (`src/chat_media.rs`)

- Supported inputs: photos (largest size), static stickers, animated sticker/video/GIF thumbnails, and image documents, taken from the current message or the message being replied to (including when replying to a photo/image document during an active `followup` window; video audio is not transcribed).
- Capped at `chat.image_max_bytes` (default 8 MiB) and sent as a `data:` base64 URL on the initial completion round; if the model invokes tools, subsequent tool-loop rounds replace the `image_url` array with plain `user_text` so follow-up rounds do not re-upload the base64 image payload.
- Requests carrying an image start without `reasoning_effort`, because with a vision turn the model otherwise spends the entire `max_tokens` budget on internal reasoning and returns an empty `content`. A text turn that still comes back empty is retried once without deliberation (`reply_is_empty` in `src/chat_style.rs`).

## Chat memory and compaction (`src/memory.rs`, [ADR 012](../adr/012-free-chat.md), [ADR 014](../adr/014-injection-ignore.md))

- Every message in an active chat is recorded in `chat_messages` with `author_id`, `author_name` (`first_name (@username)` when `username` is present and distinct from `first_name`), `role`, `flags`, and `compacted_at` (compaction acquires `Settings::chat_lock(chat_id).write()` so it never overlaps active turns holding `read()`), and forwarded messages are prefixed with `[переслано] `. Raw rows are never deleted.
- `load_memory` returns the chat's `chat_summaries.summary` (`memory.summary_max_chars` default 1500) plus up to `memory.recent_messages` (default 60) uncompacted messages (`memory.recent_max_chars` default 12_000) having `flags = 0`. Each message carries its stored `role`, so `chat_reply_with_proposal` replays history as real `user`/`assistant` turns (`format_line_with_owner` tags both the owner's historical turns and the current speaker line with `[owner]` so the bot always recognizes the owner and their conversational directives even on followup turns), preceded by a separate system message carrying `<self_memory>` from `code_inspect::load_self_memory` (`code.memory_max_rows` default 50, `code.memory_max_chars` default 1200, scoped via `code_inspect::filter_self_memory` so on non-owner turns `- [owner]` lines with a standalone `@handle` only appear when that handle matches `sender_name` or `ChatTurn.username`, while owner turns, general directives including URL/path tokens with `@`, and code facts stay visible) and `<memory>` when present; `code_inspect::speaker_owner_directives` reinforces general `- [owner]` directives plus those whose `@handle` matches the current speaker (or, on owner turns, the replied-to author header in `reply_context`, excluding unrelated participants' `@handle` rules and quoted snippet mentions) in the final user turn right before `актуальная реплика...` so prior assistant turns in history do not dilute active owner directives.
- Every `memory.compact_interval_secs` (default 600, 10 minutes), `memory_compactor` summarizes old uncompacted messages (`memory.keep_fresh` default 40, `memory.keep_newest` default 5 with `memory.compact_after_secs` default 12h, up to `memory.compact_batch_messages` default 200 / `memory.compact_batch_chars` default 12_000 per pass, `memory.compact_passes` default 3) into `chat_summaries`, marking compacted rows with `compacted_at` and pruning expired rows from `ignored_users`.

## Function tool registry (`src/tool_registry.rs`, `src/chat_tools.rs`, [ADR 015](../adr/015-tool-registry.md))

`ToolRegistry::builtin()` is the single source of truth for the schemas, visibility and research-mode filtering of all 10 function tools; `run_tool_call` (`src/chat_tools.rs`) is the only executor and enforces the per-reply budgets. Web search providers live in `src/search.rs` + `src/search_providers.rs` + `src/search_parse.rs`, multi-query research in `src/research.rs`, the deterministic `feature_status` renderer in `src/chat_status.rs`, and the page reader in `src/read_url.rs` + `src/read_url_html.rs` + `src/read_url_sites.rs`.

| Tool | Visibility | Kind | Purpose |
|---|---|---|---|
| `web_search` | `All` | `WebSearch` | Single fresh fact (1-10 results, default 5, `search.result_chars` default 2500, optional `recency`: `day`/`week`/`month`/`year`) through the automatic keyless chain (`search.provider = "auto"`: Tavily if key set -> Firecrawl v2/v1 -> DuckDuckGo -> Parallel MCP -> Exa MCP -> Startpage -> Mojeek -> Ecosia); result URLs are added to `discovered_urls` so `read_url` can open them in the same turn |
| `research` | `All` | `Research` | Multi-query survey/comparison (2 to 4 queries in parallel; each query fans out across multiple keyless engines via `public_web_search` with `search.public_soft_deadline_secs` (default 5) soft / `search.public_hard_deadline_secs` (default 12) hard deadline and cross-engine consensus ranking, up to `research.max_sources` (default 8) deduplicated ranked sources, `research.dossier_chars` (default 5000) dossier, `research.timeout_secs` (default 15) timeout, `research.cooldown_secs` (default 20) per-user cooldown, `chat.research_calls_per_reply` (default 1) per reply, max `chat.search_calls_per_reply` (default 6) total search calls per reply; [ADR 016](../adr/016-research.md)) |
| `read_url` | `All` | `ReadUrl` | Read and navigate one public `http(s)` URL from the current prompt, reply context, recent chat messages, or links discovered by `web_search`/`research`/`read_url` in the current or recent turns of the same chat (plus query-less public URLs for the owner; supports `:1-120`, `:-80`, `:raw` selectors over cached pages, special handlers for GitHub/Reddit/Wikipedia/Hacker News/crates.io/PyPI, RSS/Atom feed markdown, automatic `https` -> `http` fallback, labeled `Links:` extraction, max `chat.read_url_calls_per_reply` (default 5) calls/reply, DNS-pinned public IPv4, max `read_url.max_redirects` (default 5) redirects, `read_url.max_bytes` (default 2 MiB) / `read_url.max_chars` (default 24,000), `read_url.cache_ttl_secs` (default 600) cache; [ADR 019](../adr/019-read-url.md)) |
| `propose_feature` | `All` | `ProposeFeature` | Queue a feature request in `self-improve/inbox` (stage `plan`); after owner approval the orchestrator creates a GitHub issue |
| `feature_status` | `All` | `FeatureStatus` | Read-only queue inspection (`summary`, `details`, `links`). Owner sees the whole queue; non-owners see only their own proposals |
| `feature_confirmation` | `Owner` | `FeatureConfirmation` | Read-only list of feature requests waiting for owner approval (`DecisionGate::Issue`) with inline buttons (`В issue` / `В помойку`) |
| `inspect_code` | `All` | `InspectCode` | Read-only search or file read over `/var/lib/maksut/code` (sorting `src/` and `Cargo.toml` ahead of `tools/` and `docs/`) with GitHub blob URLs (`https://github.com/labi-le/maxwell/blob/main/<path>#L<line>`, max 5 calls/reply; [ADR 018](../adr/018-owner-code-inspection.md)) |
| `remember_self` | `Owner` | `RememberSelf` | Persist an owner conversational directive/note under a canonical short `topic` such as a participant name (when `source_url` is omitted/empty; empty `fact` deletes the topic) or a code-verified fact with its GitHub blob URL into `bot_self_memory` after `inspect_code` (max 3 calls/reply) |
| `find_stickers` | `All` | `FindStickers` | Semantic search over the owner's 15 newest sticker packs (`sticker_descriptions.json`) |
| `send_sticker` | `All` | `SendSticker` | Send at most one sticker per reply by `sticker_id`, semantic `query` (with Russian word-stem matching in `StickerCatalog::search`), or classic alias |
## Stickers (`src/stickers.rs`, `tools/build_sticker_index.py`, [ADR 010](../adr/010-sticker-replies.md), [ADR 011](../adr/011-semantic-sadness.md), [ADR 013](../adr/013-newest-sticker-packs.md))

- **Classic owner triggers (`sticker_rule`).** Standalone word/stem matches in owner messages when no supported link and no pending self-improve decision (`has_pending_decision`) is present:
  - `"да"` (in messages `<= 3` words) -> «Пизда»
  - `"нет"` (in messages `<= 3` words) -> «Пидора ответ»
  - `"ну"` (single-word message) -> «Баранки гну»
  - `"300"` / `"триста"` (including `"300$"`, `"300 баксов"`, word-bounded so `1300` / `3000` do not match) -> «Отсоси у тракториста»
  - `"молодец"` / `"молодца"` / `"молодцом"` / `"молодцы"` / `"молодчина"` -> «Молодцы, сосут концы»
  - Sadness stems (`груст*`, `депрес*`, `депрешн*`, `печал*`, `тоска`/`тосклив*`, `хандра`, `расстро*`, `подавлен*`, `поник*`, `тлен`, `паршив*`, `одинок*`) and phrases (`кошки скребут`, `нет сил`, `настроение на нуле`, `валится из рук`, `хочется плакать`) -> «Грустно везде»
  Stickers are matched by `file_unique_id` and resolved to bot-specific `file_id`s at startup via `getStickerSet`.
- **15-pack semantic catalog.** `sticker_sets.txt` lists the 15 newest non-emoji sticker packs on the owner's account, and `sticker_descriptions.json` maps `<pack_short_name>:<1-based_index>` to Russian descriptions. At startup `load_sticker_catalog` fetches live `file_id`s with `getStickerSet` and joins them by index.
- **Rebuilding the sticker index (on the host running Telegram MCP):**
  ```sh
  STICKER_NEWEST=15 uv run --with mcp --with httpx python tools/build_sticker_index.py
  ```
  The script writes `sticker_sets.txt` and `sticker_descriptions.json` atomically after each sheet.
