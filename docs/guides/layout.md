# Module map and repository layout

> **When to read this:** Read for orientation, or when you need to know which file owns a concern.

## Rust binary (`src/`, crate `maksut`)

Every module is declared in `src/main.rs` and shares imports through `src/prelude.rs`, which `src/main.rs` re-exports (`pub(crate) use prelude::*;`), so a single `use crate::*;` in a module brings in the standard prelude, `serde_json::Value`, `sqlx`, `teloxide`, `tokio` and `url` items. Do not add `use crate::prelude::*;` to a file that already has `use crate::*;`, and do not repeat an import that the prelude already provides.

**Architecture and file layout rules:**

- **Zero test code in production modules.** Production `src/<module>.rs` files must contain only production types and functions: never `#[cfg(test)] mod tests`, `#[test]`, `#[tokio::test]`, or `#[cfg(test)]` helper constructors/wrappers. All tests sit in sibling `src/<module>_test.rs` files wired at the bottom of `src/main.rs`, and shared test fixtures/builders sit in `src/test_support.rs` (process, HTTP, and settings fakes) and `src/feature_support.rs` (the recording Bot API server: `FeatureApi`, `feature_read_request`). The same holds for Python (`tools/<name>.py` vs `tools/test_<name>.py`).
- **One responsibility per file (`<= 500` lines target for production modules).** The target applies to production `src/<module>.rs` files: do not append new subsystems to `src/chat.rs` or `src/self_improve.rs`. Each concern (for example: search providers, multi-query research, LLM HTTP transport, reply styling, queue storage, status views) belongs in its own focused module and corresponding subsystem `*_test.rs` file. Test modules `src/*_test.rs` are grouped by subsystem (`chat_test.rs`, `chat_status_test.rs`, `memory_test.rs`, `read_url_test.rs`, `research_test.rs`, `self_improve_test.rs`) and may exceed the target. Current test modules: `browser_test`, `caption_test`, `chat_embeddings_test`, `chat_status_test`, `chat_test`, `code_inspect_test`, `cookie_refresh_test`, `cookies_test`, `database_test`, `delivery_test`, `diagnostics_test`, `download_test`, `download_videos_test`, `handler_test`, `ignore_window_test`, `image_fetch_test`, `images_test`, `links_test`, `media_cache_test`, `media_test`, `memory_test`, `process_test`, `read_url_test`, `research_test`, `self_improve_test`, `stickers_test`, `tool_registry_test`, `user_errors_test`, `video_convert_test`, `youtube_test`.

- `src/main.rs`: entrypoint, process-wide limits from the config (`media.max_files`, `media.max_tiktok_photos`, `media.user_download_limit`, `telegram.file_limit_bytes`, `media.max_bytes`, `media.download_timeout_secs`, `media.max_video_duration_secs`, `telegram.request_timeout_secs`, `telegram.pool_idle_timeout_secs`, `telegram.tcp_keepalive_secs`, `media.cookie_refresh_timeout_secs`, `media.youtube_probe_timeout_secs`, `media.max_metadata_bytes`, `media.mp4_mux_headroom`, `media.max_twitter_json_bytes`, `media.max_video_dimension`, `media.max_video_pixels`), background task spawns (`load_sticker_catalog`, `memory_compactor`, `chat_indexer`, `improvement_notifier`), and the `teloxide` dispatcher (`distribution_function(|_| None::<i64>)` so a slow download in one chat never serializes other updates)
- `src/config.rs` + `src/config_sections.rs` + `src/config_validate.rs` + `src/config_validate_media.rs` + `src/config_validate_extras.rs` + `src/retry.rs`: the configuration contract (`Config` root, section structs with their defaults, `RetryPolicy`), the startup loader (`Config::load`: defaults -> `config.toml` or `MAKSUT_CONFIG` -> legacy env overrides), per-key range validation that keeps the security bounds, and the process-wide `config()` accessor installed once by `Settings::load()`
- `src/logging.rs`: `tracing-subscriber` stderr formatter (module target, `file:line`, `#[instrument]` function spans) filtered by `log.level`, installed right after the config
- `src/chat_urls.rs`: per-chat discovered-URL cache (`remember_urls`, `recent_urls`, `chat.discovered_url_ttl_secs`, `chat.discovered_urls_per_chat`) and repository blob link expansion (`expand_repo_blob_links`, `resolve_repo_target`)
- `src/settings.rs`: `Settings::load()` (defaults, then `config.toml` or `MAKSUT_CONFIG`, then env overrides and validation), startup checks for `OWNER_ID`, the paths (`paths.database_url`, `paths.download_dir`, `paths.cookies_file`, `paths.cookie_refresh_url`, `paths.self_improve_dir`), `LLM_*`, `search.provider`, `media.max_bytes` and `TAVILY_API_KEY`, per-chat/per-user `RwLock`s (`chat_locks`: shared per-chat `read()` / exclusive compaction `write()`, plus per-`(chat_id, user_id)` `user_turn_lock`), download semaphore (`Semaphore::new(config().media.concurrent_downloads)`, default 2), and per-user download rate-limit semaphores
- `src/handler.rs`: top-level Telegram update routing (`handle_message`, `handle_callback_query`), `/maksut status|on|off` group control, owner standalone sticker triggers (`reply_with_sticker`), link extraction and download slot acquisition, and delegation to free chat or self-improve handlers
- `src/links.rs`: URL allowlist (`allowed_url`) for YouTube, Pinterest, X/Twitter, Instagram and TikTok; short-link resolution (`pin.it`, `vm.tiktok.com`, `vt.tiktok.com` via `resolve_short_link` with pinned DNS and bounded redirects)
- `src/download.rs`: end-to-end download orchestration for a single URL: short-link resolution, 24-hour `media_cache` lookup, parallel/sequential dispatch across video and photo pipelines, on-demand cookie refresh retry, album grouping, delivery, source-message deletion, and failure recording
- `src/download_videos.rs`: `yt-dlp` video/audio invocation, YouTube pre-probe selection, `after_move` description capture, `ffprobe` audio-stream verification, and `ffmpeg` transcoding integration
- `src/process.rs`: `DownloadProcess` lifecycle (`setsid` process-group isolation on Unix so `SIGKILL` terminates both `yt-dlp` and any child `ffmpeg`, bounded `stdout`/`stderr` capture tasks, `Drop` reaping, and `stderr_detail` classification)
- `src/youtube.rs`: single-video YouTube metadata probe (`yt-dlp -J`) and format selector that picks the highest-resolution H.264 + AAC stream pair fitting `media.max_bytes` with `media.mp4_mux_headroom`
- `src/video_convert.rs`: `ffprobe` stream inspection (moving video vs cover art, audio track presence, dimension/pixel limits) and `ffmpeg` transcoding to MP4 (H.264/yuv420p + AAC, capped at 1920px per side with even-dimension padding)
- `src/images.rs`: photo metadata extraction for Pinterest, Instagram, X/Twitter (`tools/twitter_images.py`), and TikTok photo posts (`/@user/photo/<id>` from `webapp.video-detail`), CDN URL allowlisting (`image_cdn_url`), and `permitted_ipv4`
- `src/image_fetch.rs`: DNS-pinned HTTPS client cache (`PINNED_CLIENTS`) and streaming image downloader (`save_image_response`) with MIME verification, size caps, and `.part` atomic persistence
- `src/media.rs`: media file classification by extension (`MediaKind`: `Photo`, `Video`, `Audio`, `Document`) and directory scanning
- `src/delivery.rs`: Telegram sending: adjacent compatible media grouping into albums of 2 to 10 items (`sendMediaGroup`), caption deduplication across album items, silent delivery (`disable_notification = true`), single-item document fallback on explicit Telegram rejection, and `file_id` collection for `media_cache`
- `src/caption.rs`: HTML caption builder (`<title>\n\n<description>`, `<code>От first_name</code>`, clickable `Ссылка`) truncated cleanly within Telegram's 1024 UTF-16 code-unit limit
- `src/source_message.rs`: deleting the sender's original link message after full delivery, or warning when the bot lacks `can_delete_messages`
- `src/media_cache.rs`: 24-hour SQLite `media_cache` (keyed by SHA-256 of bot token + chat id + normalized URL with query, capped at 200 newest entries globally)
- `src/cookies.rs`: Netscape cookie jar validation (`check_cookies`), per-source cookie domain matching, and temporary cookie copy preparation for `yt-dlp`
- `src/cookie_refresh.rs`: async HTTP client for the `cookie-refresh` sidecar (`POST /refresh`) and auth-failure classification that triggers a single retry; the 5-second per-source deduplication window (`CACHE_SECONDS = 5.0`) lives in `tools/cookie_refresh_service.py`
- `src/diagnostics.rs`: structured failure recording into SQLite (`download_failures` and `download_failure_events`, capped at 200 parent rows and 12 events per failure), incomplete-delivery warning/trace reporting (`report_incomplete_delivery`), and selection of the most actionable user-facing cause (`source_user_diagnostic`)
- `src/user_errors.rs`: mapping internal stages and `yt-dlp` / HTTP / Telegram errors into safe Russian user-facing messages without leaking raw stderr, URLs, or tokens
- `src/database.rs`: SQLite connection pool setup (`open_database`) and schema creation (`group_settings`, `download_failures`, `download_failure_events`, `chat_turns`, `chat_messages`, `chat_summaries`, `chat_embeddings`, `memory_meta`, `ignored_users`, `bot_self_memory`, `media_cache`)
- `src/chat.rs`: free-chat turn orchestration (`reply_with_chat`, `chat_reply_with_proposal`): ownership and group gating, prompt assembly (including multimodal snapcompact archive frames on round 0), the tool call loop (`chat.tool_rounds`, default 8) over `chat.max_tokens` (default 4000) / `chat.status_max_tokens` (default 1500) / `chat.research_max_tokens` (default 4000), empty/length-clipped reasoning fallback (`reply_is_empty`), and delivery (`ChatReply` Telegraph publishing or multi-chunk splitting, sticker, decision markup, addressed error reply, `chat_messages` recording)
- `src/chat_client.rs`: `ChatConfig` construction, per-user pacing and cooldowns (`chat.cooldown_ms` default 3000, `chat.concurrency` default 4, `llm.request_timeout_secs` default 40, `chat.followup_window_secs` default 180), per-chat recent discovered URL cache (`chat.discovered_url_ttl_secs` default 1800, `chat.discovered_urls_per_chat` default 32), reasoning configuration (`llm.reasoning_effort`, env override `LLM_REASONING_EFFORT`, default `low`), system and owner/followup prompt blocks (`docs/communication-guide.md` via `include_str!` + `GUIDE_PREFIX` + `SYSTEM_PROMPT`, `OWNER_CODE_PROMPT`, `OWNER_FEATURE_PROMPT`, `FOLLOWUP_PROMPT`), OpenAI-compatible completion transport (`complete`, `complete_with`, `one_shot`, `feature_title`, `CompletionRequest`, `CompleteError`), and the bounded `/embeddings` call (`embed`)
- `src/typing.rs`: typing action keepalive (`spawn_typing_keepalive`, `chat.typing_keepalive_secs` default 4) with the `AbortOnDrop` guard
- `src/addressing.rs`: addressing primitives shared by chat and the router: `BOT_NAME_FORMS`, `strip_name`, `trim_name_edges`, `AddressKind`, `address_kind`, `explicit_mention`, `named_content_left`, `reply_to_bot`
- `src/chat_media.rs`: vision attachments (`message_image`, `message_has_own_photo`, `acquire_image_permit`, `download_image`, `ChatImage`, `base64_encode`) bounded by `chat.image_concurrency` (default 4) and `chat.image_max_bytes` (default 8 MiB), plus free-chat input/attachment resolution (`resolve_chat_input`, `ResolvedChatInput`)
- `src/router.rs`: pre-model reply decision (`Decision`, `RouterInput`, `Router::decide`, `decide_rules`) with `[router]` modes `off`/`rules`/`jev` and the rules fallback
- `src/jev.rs`: TypeSafe System One (`Jev`) client: one `choice` question, no redirects, `router.jev_model`, `router.jev_timeout_ms`, `router.jev_max_response_bytes`, `router.jev_concurrency` (bounded by a shared semaphore), `router.jev_min_confidence`, and `None` on any failure
- `src/chat_status.rs`: deterministic `feature_status` answers (`status_answer`, `status_answer_grounded`, `resolve_status_reply`, `style_status_reply`) for the `summary`, `details` (including `issue_created` items and their GitHub issue URLs) and `links` views
- `src/chat_style.rs` + `src/chat_text.rs` + `src/telegraph.rs`: prompt addressing (`chat_prompt`, `resolve_addressed_chat`), spam/parroting suppression (`is_repeated_user_spam`), author/reply-context formatting (`display_author_name`, `format_reply_context`), fence-aware chunking (`split_message`, capped by `chat.reply_max_chars`, default 3900), Telegraph (`telegra.ph`) article publishing for long replies (`maybe_publish_reply`), reply shaping (`style_reply`, `style_chat_reply`, `flatten_reply_text`, `style_research_reply`, `shorten`, `truncate_text`, `format_moscow_time`, citation sanitizing), and sticker/feature/stop-followup trigger detection
- `src/chat_tools.rs`: function-tool execution (`run_tool_call`, `ToolContext`, `ToolState`) and per-reply budgets (`chat.read_url_calls_per_reply` default 5, `chat.inspect_code_calls_per_reply` default 5, `chat.remember_self_calls_per_reply` default 3, `chat.search_calls_per_reply` default 6, `chat.research_calls_per_reply` default 1, `chat.chat_search_calls_per_reply` default 3)
- `src/search.rs` + `src/search_providers.rs` + `src/search_parse.rs`: omp-style search client (`SearchClient`, `SearchProvider`: `Auto` sequential keyless chain, `Public` multi-engine consensus fanout, `Parallel`, `Exa`, `Firecrawl` v2/v1, `Tavily`, `DuckDuckGo`, `Startpage`, `Mojeek`, `Ecosia`), recency filters, MCP JSON-RPC/SSE parsers, and HTML/DOM result extraction (`extract_search_results`, `extract_startpage_results`, `extract_mojeek_results`, `extract_ecosia_results`, `clean_text`)
- `src/browser.rs`: Firefox 147 / Linux x86_64 navigation header set (`USER_AGENT`, `HTML_ACCEPT`, `navigation_headers`) shared by `read_url` and the public HTML search engines; header-only emulation, no cookies, JS, or TLS fingerprint
- `src/research.rs`: multi-query research (`ChatConfig::research`, `collect_research` over `public_web_search`, `normalize_url`, dossier rendering, `research.cooldown_secs` default 20)
- `src/tool_registry.rs`: single source of truth (`ToolRegistry`, `ToolSpec`, `ToolKind`, `ToolVisibility`) for function-tool schemas, visibility (`All` vs `Owner`), research-mode filtering, and authorization (`ToolRegistry::find`)
- `src/read_url.rs` + `src/read_url_html.rs` + `src/read_url_sites.rs` + `src/read_url_cache.rs` + `src/read_url_text.rs`: public web page reader (`read_url` tool): URL allowlist across prompt/reply/recent-chat/discovered links, `:A-B`/`:-N`/`:raw` line selectors over cached pages, special site handlers (GitHub raw/issues, Reddit JSON, Wikipedia REST summary, Hacker News item API, crates.io, PyPI), RSS/Atom XML feed markdown rendering, SSRF/DNS-pinning guard, `https` -> `http` connection fallback, manual redirect validation, HTML complexity guard, `dom_query` + `dom_smoothie` readability extraction with short-stub fallback and `Links:` footer, charset decoding (`chardetng`/`encoding_rs`), and 10-minute in-memory cache
- `src/code_inspect.rs`: `inspect_code` (`ToolVisibility::All`) implementation over `/var/lib/maksut/code` (`code.max_file_bytes` default 256 KiB, symlink skipping, extension allowlist, `SKIP_DIRS`, GitHub blob URL formatting) and owner-only global verified self-knowledge (`bot_self_memory`: `record_self_fact`, `load_self_memory`)
- `src/memory.rs` + `src/snapcompact.rs`: chat history storage (`chat_messages`), lexical flag detection (`FLAG_INJECTION`, `FLAG_SECRET`, `FLAG_JUNK`, `FLAG_IGNORED`), 24-hour prompt-injection ignore window (`ignored_users`), context loader (`load_memory`), and 10-minute deterministic model-free snapcompact archival (`memory_compactor` -> `chat_summaries` via `snapcompact::build_snap_archive` with `font_8x13.bdf` 1-bit PNG frames)
- `src/chat_embeddings.rs`: embeddings index over chat history. `embed_texts` is the bounded `/embeddings` transport under `retry.llm` (`memory.embedding_max_response_bytes`, `memory.embedding_dim`, provider `index` honoured); `chat_indexer` writes unit vectors into `chat_embeddings` in bounded `memory.embedding_batch` calls every `memory.embedding_interval_secs`, oldest pending row first, and leaves failures pending; `index_pending`, `coverage` and `reindex` back the owner-only `chat_index` tool. Indexing requires `flags = 0`. Retrieval is `src/chat_search.rs` ([ADR 026](../adr/026-chat-history-rag.md))
- `src/chat_search.rs`: on-demand chat history retrieval behind the `chat_search` tool. Embeds the query, scores at most `memory.search_scan_rows` rows of the current chat, drops scores below `memory.search_min_score`, deduplicates by message id and text, merges the newest `memory.search_recent_messages` unflagged rows, and caps each text at `memory.search_chunk_chars` and the payload at `memory.search_max_chars`; queries require `flags = 0` ([ADR 026](../adr/026-chat-history-rag.md))
- `src/stickers.rs`: classic owner word-trigger sticker table (`sticker_rule` matched by `file_unique_id`) and semantic 15-pack catalog (`StickerCatalog`, `find_stickers`, `send_sticker`) loaded from `sticker_sets.txt` and `sticker_descriptions.json`
- `src/improve_store.rs`: self-improve queue storage and its only writer: temp-file `atomic_write` with a process-wide sequence, `inbox/`+`outbox/` scanning (`read_queue_tasks`), plan/refine queueing (`PlanProposal`, `RefineProposal`), and the `record_decision` marker gate
- `src/improve_views.rs`: bounded status JSON (`status_snapshot`, `status_snapshot_for`, `status_overview`, `pending_confirmation`), task view building (`task_view`), `bound_result` size capping, API-key redaction, and the shared `format_status` renderer
- `src/improve_commands.rs`: owner command vocabulary (`одобри`, `отклони`, `отмени`, `подними`, `опусти`, `приоритет`), short/prefix/suffix task ID resolution, batch cancel, and inline approval keyboard building (`decision_markup`)
- `src/self_improve.rs`: chat-side self-improvement control plane: `/improve` commands, natural-language owner actions, inline approval callbacks, and `improvement_notifier` (outbox polling routed through `spawn_blocking`)
- `src/cleanup.rs`: startup cleanup of stale temporary download directories in `DOWNLOAD_DIR`

## Python helpers and host-side services (`tools/`, `cookie_refresh/`, `self_improve/`)

- `tools/twitter_images.py` (`test_twitter_images.py`): runs inside the `maksut` container under `/opt/yt-dlp/bin/python`; uses `yt-dlp`'s `TwitterIE` to extract photo URLs, description, and `has_video` from X/Twitter posts
- `tools/export_chrome_cookies.py` (`test_export_chrome_cookies.py`): runs on `pc` or `notebook` over SSH; decrypts Chrome's SQLite cookie store (`v10`/`v11`) via the host keyring and outputs a filtered Netscape cookie jar on stdout
- `tools/cookie_refresh_service.py` (`test_cookie_refresh_service.py`): HTTP sidecar (`cookie_refresh/Dockerfile`, `:8080`) that SSHes to `pc` and `notebook`, picks the freshest Chrome profile containing cookies for the requested source, and atomically writes `cookies.txt` (`0600`)
- `tools/self_improve_orchestrator.py` (`test_self_improve_orchestrator.py`): host-side systemd user service (`packaging/maksut-self-improve.service`); polls `self-improve/inbox`, writes `status: "proposed"` to `outbox`, and on owner approval (`approvals/`) opens a GitHub issue via `gh` (`status: "issue_created"`)
- `tools/deploy_hook.py` (`test_deploy_hook.py`): GitHub webhook receiver behind the host reverse proxy; verifies `X-Hub-Signature-256`, accepts only a successful `publish-image` `workflow_run` on `main`, answers 202, and runs one deploy at a time ([ADR 024](../adr/024-event-driven-deploy.md))
- `tools/published_deploy.py` (`test_published_deploy.py`): entry point for the timer and the webhook; checks `self-improve/off`, extracts `tools/auto_deploy.py` from `origin/main`, and runs that copy so deploy logic never comes from the working tree
- `tools/auto_deploy.py` (`test_auto_deploy.py`): host-side oneshot deploy; fetches `origin/main`, pulls `ghcr.io/labi-le/maxwell:<sha>` built by `.github/workflows/publish-image.yml`, materializes `compose.yaml` from that commit, extracts the same commit's sources into `self-improve/code/<sha>` for `inspect_code` (`MAKSUT_CODE_DIR`), recreates `maksut` with `--no-build`, records `self-improve/deployed_sha`, and prunes the previous export and `<sha>` image tag; the checkout is fast-forwarded only when it is on `main` and clean, and never blocks the deploy ([ADR 023](../adr/023-auto-deploy-from-remote.md)); the webhook (`packaging/maksut-deploy-hook.service`) is the only trigger, and `make deploy-now` runs the same shim by hand
- `tools/pr_review.py` (`test_pr_review.py`): GitHub Actions PR reviewer (`.github/workflows/pr-review.yml`) that posts automated architecture + performance reviews using `REVIEWER_TOKEN`
- `tools/omp_worker.py` (`test_omp_worker.py`): standalone sandbox helper that runs an `omp` agent inside a disposable read-only Docker container connected only to `maksut-self-improve-internal` (`self_improve/proxy.Dockerfile` + `self_improve/proxy.py`); retained as an isolated utility while live feature intake routes through GitHub issues (`tools/self_improve_orchestrator.py`)
- `tools/build_sticker_index.py`: host-side utility using Telegram MCP and a vision model to refresh `sticker_sets.txt` and `sticker_descriptions.json`
- `tools/e2e_telegram.py` (`test_e2e_telegram.py`): local pre-PR live check that drives the deployed bot through the `telegram-mcp` user session (`self-improve/e2e.json`, `example.e2e.json`, `MAKSUT_E2E_*`); verifies the bot answered, its message carries no literal `parse_mode` markup and no token-shaped value, and — when configured — that a media link produced a downloadable message with an audio stream (`ffprobe`) and that a sticker request produced a sticker. It prints `SKIP` with a reason when the config or the MCP server is absent, so `python3 -m unittest discover -s tools` stays green on hosts without a Telegram session
